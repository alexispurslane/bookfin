# Give every derived-file write one owner that holds the download

The invariant: a write of a derived file (the admitted record, a page map, a survey, an OCR cache) must finish inside a Downloads read of its download, so that a removal waits for it. Today each writer keeps it in its own way:

- The admitted record: ReaderSession.derivedWrites, wired beside loadDocument, and a separate wait in measureDownloadedOutline (lib/reader/platform_io.dart). Added by boo-yjq6.
- Surveys: a new ReaderSession._lend for each write (SurveyFiles).
- Page maps: nothing. BookPageMaps.write (lib/reader/epub/page_maps.dart) writes into the layout directory outside any read. A removal during such a write can fail with 'Directory not empty', or the write can make the layout directory again after the removal deleted it, so the download folder keeps a stray map.

A new caller of loadReadingDocument or loadPublication must know to wait, and each new derived file adds another thing to remember (boo-yjq6 review, finding D1). Design one owner for the invariant, for example: the read callback of Downloads.readLocalFile gets a hold(Future) that keeps the lend until the work ends, and the loaders register their own writes; or DerivedBookFiles.write requires a lend. Then the session and the outline measure stop waiting by hand, and page maps get the lend too. The redesign keeps boo-yjq6's behavior, so it follows that fix.
