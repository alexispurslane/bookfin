# A table row that splits across pages can leave a blank page

Found in tc-4f3q (corpus run on the renderer after te-4cez merged). In Standard Ebooks' Hamlet, act 1 (epub/text/act-1.xhtml, section 4) at 412 x 671 at 20 pixels, the main run cuts page 12 as PageStart(13, 50): one slice of 10 pixels with no line, no image and no place (startPlace and endPlace are null). Pages 11 and 13 hold the text before and after it, with visible characters 2711 to 3073 and 3073 to 3409. Row 50 of the act's dialogue table is a speech of about 30 verse lines, taller than a page, so te-4cez splits it, and the blank page seems to be a fragment of that row that holds only cell spacing or padding. A reader turning pages sees an empty page.

A run from that page start also disagrees with the main run: its first page reports visible characters 44 to 44, where the main run's page 12 reports 3073 to 3073. The page source keys and orders pages by such values, so the shown page and the scrub bar can disagree for this page.

Related: t6-vbcw (the space above a split row's first fragment).

## Acceptance Criteria

- No page of Standard Ebooks' Hamlet at either corpus page settings is blank, and a run from every page start cuts the same pages as the main run (BOOKFIN_EPUB_CORPUS=1 flutter test test/reader/epub/corpus_test.dart --plain-name se-hamlet).
- A table test holds a row whose split leaves a fragment with no line, and shows that no page holds only that fragment.

Corpus after (runs from every page start): Hamlet, Plato's Dialogues and Roget's Thesaurus have no blank page and no differing run at both page settings.
