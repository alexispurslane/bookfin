# Give PDF editions a text outline from PDFium bookmarks and the text layer

Step 8 of design A in docs/plans/cross-edition-places.md. The PDF outline comes from PDFium bookmarks, and the visible characters of each page come from the text layer. Until this ticket, a PDF edition refuses a landing.


## Notes

**2026-11-11T20:15:34Z**

Built on branch t3/30cd0bb4. measureDownloadedOutline measures a PDF through PdfRuntime.measureOutline -> measurePdfOutline (lib/reader/pdf_outline.dart): it opens its own PDFium handle on pdfrx's worker isolate, reads the bookmarks (GoTo actions too, /XYZ heights), and counts each page's text layer in ~8 ms low-priority slices; only counts reach the UI isolate. pdfOutlineOf assembles the outline: parts page:N, bookmarks at every depth (as the EPUB contents depth), each starting after the characters above its /XYZ place. Decisions: a PDF without bookmarks has no entries -> noChapters; a page without a text layer holds 0 characters when at least half the pages have text (picture or blank page); in a scan, each such page counts 1600 characters (places fall by pages), because whole-book OCR costs minutes and refusing loses every scanned book; a PDF reading place lies at its page start (follow-up t3-tkpa for text-view character offsets). TextOutline now sorts entries by start itself. Damaged or encrypted PDFs throw FormatException -> unreadable. Fixture: test/reader/fixtures/outline/parts-book.pdf (Typst, CC0). Captures: ~/.cache/bookfin/previews/boo-z3is/round2/.
