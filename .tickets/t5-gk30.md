# Open EPUBs whose contents name a file that the book lacks

Found by t3-a4fi on the user's Jellyfin library, on 2026-11-11. Bookfin refuses 3 of the 12 EPUB ebooks on the server, so the reader cannot open them and Crossings cannot measure their outlines.

- 2 books: 'EPUB contents points outside the reading order.' In each book, one entry of the NCX contents names a file that is not in the archive. Publication.admit (lib/reader/epub/publication.dart) refuses the whole book for that one entry. Other readers drop the entry and open the book.
- 1 book: 'EPUB entry exceeds limits or uses unsupported ZIP features.' A quick check found no entry over the size or ratio limits and no encrypted entry or unusual compression, so the cause is still unknown.

Decide whether an NCX entry that names a missing file is dropped with the rest of the book kept, and find which ZIP check refuses the third book. Do not commit the books: they are the user's private files. Fetch them again from Jellyfin through T3's secret input.
