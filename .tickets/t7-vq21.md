# Keep corrupt admission quarantine under download ownership

Found during boo-j7gh review at 40a6a233207a52838f28d6d01a8d14df45e4221a, finding D1 (medium, nonblocking, inherited). The original report is docs/evidence/boo-j7gh-review.json.

Trigger: BookSearch opens a corrupt saved admitted record through the speech EPUB reader (_keptOrAdmittedEpub) or MOBI reader (keptMobi), after the factory has returned from Downloads.readLocalFile.

AdmittedBooks._kept catches FormatException and renames the saved record to publication.unreadable (lib/reader/admitted_books.dart:290). The speech worker deliberately does not capture the download hold. This read therefore mutates a derived file outside its download owner. Healthy-record reopen tests do not prove the corrupt-record path is read-only.

Static provenance: git diff a85c8789e9a14c4d978f94e64db3c6cacfafd8a0 40a6a233207a52838f28d6d01a8d14df45e4221a -- lib/reader/admitted_books.dart lib/reader/mobi.dart is empty. The original platform_io.dart already creates the later worker read through the same admission functions. The rename is present at the original base. No corrupt-record runtime reproduction has been run for this finding.

Related prior work: t4-3o9f assigns derived-file changes to a Downloads read/hold; t7-rcyp preserves corrupt records through quarantine; t2-v4eq and boo-5ivg describe speech reads as non-writing but did not account for this exception. No existing ticket specifically covers this corrupt-record ownership gap.

Keep this separate from boo-j7gh, whose settled scope extracts traversal and reuses the owned outline without changing admission behavior.

## Acceptance Criteria

Reproduce the corrupt-record mutation through a real BookSearch worker read with a meaningful failing test for both EPUB and prepared MOBI. Keep worker reads non-mutating, and perform quarantine only through the download owner while preserving corrupt bytes and normal re-admission behavior. Test removal/read coordination so quarantine cannot outlive its download ownership. Preserve admission revision and CSS dependencies, ordinary reader recovery, speech cache/revision identity, and healthy reopen behavior. Use Nix with concurrency at most two and record red/green and affected checks; make no Android latency claim.
