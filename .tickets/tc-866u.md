# Search the book in worker isolates with today's matching rules

Goal: search over the native DOM that finds the same hits as reader.js (searchPublicationText and searchBook) and runs off the UI isolate.

Design sections: "Layout off the frame path" (search row), "Places / Rules" (search hit).

Files: lib/reader/epub/search.dart (new), test/reader/epub/search_test.dart.

Interfaces:

```dart
class SearchSection {
  final int index; final String path; final String xhtml; final String spine;
}
class SectionHits {
  final int index;
  final List<(ReadingLocation, String)> hits; // location, excerpt
  final bool incomplete; // more than 500 in this section
  final bool failed;
}
/// Runs inside Isolate.run.
List<SectionHits> searchSections(List<SearchSection> sections, String query,
    List<ContentsEntry> contents, String packagePath);
```

Rules (reader.js): the query has 1 to 256 characters, else the error 'Enter between 1 and 256 characters.'. Lowercase folding. Any white space folds to one space. A change of block element (P, DIV, LI, H1 to H6, BLOCKQUOTE, TD, TH, PRE, SECTION, ARTICLE) adds a space. Skip text under hidden, aria-hidden="true", a style attribute with display:none or visibility:hidden, script, style and template. At most 500 matches per section ('Search is incomplete. Only the first 500 matches per chapter are shown.') and 500 in total ('Search is incomplete. Only the first 500 matches are shown. Use a longer phrase.'). A section that fails gives 'Search is incomplete. A chapter could not be searched. Retry or use Contents.'. The excerpt is the matched text, at most 160 characters. Each hit location comes from hitLocation (tc-sqp7). The pager (tc-mxfp) sends about 8 sections per Isolate.run and checks for a cancel between batches.

## Notes

**2026-11-08T21:25:19Z**

Built lib/reader/epub/search.dart: searchSections (the worker side) and searchBook, which sends batches of 8 sections through an IsolateHop (compute by default), asks isCurrent before and after each batch, and joins the hits into a ReaderSearchReport with reader.js's limits and errors. So the pager's search is one call. Interface changes: SearchSection.xhtml is the UTF-8 bytes (Uint8List), decoded in the worker as the page source does, because decoding on the UI isolate cost 5 ms for Moby-Dick. places.dart gains spineSteps(opf), every spine step from one parse: spineStep once per section cost 124 ms on the UI isolate for Moby-Dick's 145 sections. Proof against reader.js: a temporary recorder ran reader.js searchBook in headless Chromium 138 over the 3 showcase books and the 7 trial books with 13 queries (the, and, said, harbour, of the, It was, whale, e, Chapter, a left double quote, o plus a right single quote, NEVER, the end). All 130 reports have the same error and the same hits in the same order: 21806 hits with equal CFI, resource, quote and excerpt. Chapter labels differ only in 53 hits of se-poetry, where Publication.contents folds U+FEFF to a space (new ticket td-vjzg). search_test.dart keeps all 130 reports as counts, errors and 16-digit digests. The trial rows run when .cache/epub-trial/books exists. Moby-Dick (1.46 MB of XHTML) on the host under load 9 to 15: a search that reads the whole book takes 250 to 340 ms in 19 batches, median 13 ms per batch, longest 20 to 80 ms. The UI isolate builds the sections in 6 ms. The same work in one isolate takes 100 ms, so most of the time is the cost of 19 isolate hops. reader.js took 380 to 580 ms for the same queries.
