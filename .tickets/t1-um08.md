# Lay out a long table in steps of rows, and resume inside it without laying out the rows above

Found in tc-4f3q (corpus run). A table is one flow item, and a layout step ends only after a flow item, so one step lays out the whole table on the UI isolate. A run that starts at a page start inside a table (PageStart(item, row)) lays out the whole table again before it cuts its first page.

Measured on the host (JIT, flutter test): Gorgias in Standard Ebooks' Plato, Dialogues (epub/text/gorgias.xhtml) is one table of 266,000 visible characters in 1,082 rows, because Standard Ebooks sets dialogue as a table of speaker and speech. layoutSection takes 1,086 ms in one step, and a run from a page start in its middle takes 562 ms before its first page. Other books with such tables: Ulysses chapter 15 (one table of 265,000 characters), the other Plato dialogues (100,000 to 220,000 characters each), every Standard Ebooks play (25,000 to 40,000 characters per act), and Gutenberg's Roget's Thesaurus (one table of 1,740,000 characters in 797 rows). On the phone, which is 1.5 to 2.5 times slower, opening such a section or a saved place in it freezes the UI for seconds. That breaks the design's step rule (Steps: a step stops after the paragraph that crosses the budget) and AGENTS.md engine rule 1.

The corpus run limits its runs from page starts to 100 per section because of this (test/reader/epub/corpus/check.dart _checkRuns). When this is fixed, raise or remove that limit.

Related: te-4cez splits a row that is taller than a page and touches the same code.

## Acceptance Criteria

- A layout step that starts a table stops after the row that crosses the budget, and the next step goes on with the next row.
- A run from a page start inside a table measures and lays out no row above the page start, beyond what the column widths need. Column widths are computed once per table and section layout, not once per run.
- The property that a run from any page start cuts the same pages holds with tables.
- The corpus run's slow-item list has no table over 8 ms for Gorgias and Roget's Thesaurus at 412 x 671 at 20 pixels, or the remaining cost is recorded with numbers.
