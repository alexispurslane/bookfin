# Draw an embedded face that fails to load in the reader font, and draw variable embedded faces at their CSS weight

Found in tc-nh0b. prepare.dart names a run's family '<fontPrefix>-<family>' for every embedded face that a sheet declares with a readable source. The parser already skips WOFF 2, EOT and SVG sources, so those faces use the reader font. But a face whose file is missing or damaged is skipped by BookFonts.load, and layout.dart then draws its runs in the platform default font (Roboto on Android), not in the reader font as the design says. Fix in layout.dart: give ui.TextStyle and ui.StrutStyle fontFamilyFallback: const [readerFontFamily]. Second point: once the opsz and wght variations apply only to the reader font, a variable embedded face draws at its default instance (the Outfit test fixture draws Thin). Chromium sets a variable face's wght axis from font-weight and its opsz from the text size. Decide whether embedded faces get wght = RunStyle.weight and opsz = RunStyle.size.

## Acceptance Criteria

A run in an embedded face whose file does not load measures the same as the reader font. A variable embedded face at font-weight 400 draws at wght 400, if the decision is to copy Chromium.

**2026-11-08T20:36:18Z**

Implementer: fontFamilyFallback alone cannot pass the first criterion in tests. flutter test always runs flutter_tester with --use-test-fonts, which resolves every unknown family name to its test font, so a family fallback never applies. On a device it applies, but the fallback reader font then takes the failed face's wght, so bold text draws in the reader font's true bold. So BookFonts records which families registered (BookFonts.missing), and layout draws a family that a load named but that did not register in the reader font, with the reader font's variations. fontFamilyFallback: const [readerFontFamily] stays on the text style for characters that a face lacks (tested with an accented letter in the ASCII Outfit fixture). The strut needs no fallback, because it uses the mapped family. Flutter 3.47 already sets a variable font's wght from fontWeight when no wght variation is given, so the Outfit fixture drew at 400, not Thin. Layout still sets wght = RunStyle.weight explicitly, so weights such as 450 match Chromium.
