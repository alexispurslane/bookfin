# Restore the record journal at launch without replaying every saved action

Found in the code survey of November 12 (main at f9f26500). Nothing was run for this finding. Status: confirmed code path, estimated scale. Playback saves one resume action for each media-second (lib/playback/playback.dart:1370). At launch, `_readRows` (lib/playback/store.dart:1535) decodes every stored action, and `RecordJournal.receive` (lib/sync/journal.dart:209) copies, validates and keeps each one in memory. Ticket t6-t9po measured about 20 microseconds for each action on the Mac. One month at 2 hours a day is about 216,000 actions, so the restored book and position wait for seconds, and the heap holds every action. Keep every action on disk, as the November 3 decision says. Restore from the rows that the same transaction already writes (record_versions, record_coverage, pending, cursor), and read a retained action from SQLite only when an operation needs it. Keep the full replay for the invariant checker and for salvage.
