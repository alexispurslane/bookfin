# Cut the time to draw an EPUB scrub deck page below 0.3 s

boo-foo7 measured the EPUB scrub deck on emulator-5554 (SwiftShader software GPU, host load 6 to 15 on 10 cores). One page in the same section took 0.6 to 0.8 s from request to decoded image, and a page in a new section 1.4 to 1.7 s. The parts: hidden rendition layout (rendition.display) 185 to 450 ms in a section and about 1 s for a new section, drawing the page to a JPEG 100 to 160 ms, the WebView bridge 100 to 280 ms, and the JPEG decode in Flutter 150 to 200 ms. PDF pages take 27 to 93 ms. Measure on a phone first. Then look at the epub.js display path of the hidden rendition, which seems to lay out again for a place in the section that it already shows, and at a smaller image or a raw transfer instead of a base64 JPEG.

**2026-11-08T17:00:05Z**

boo-duaq measured EPUB scrubs on an emulator profile build (bookfin-duaq AVD, SwiftShader software GPU, host load 12 to 25 on 10 cores), with atrace, the Dart VM timeline and Choreographer logs.

The stalls in the note above did not come from the bridge. With hybrid composition, the default of flutter_inappwebview, Flutter rasterizes on the Android main thread whenever a platform view shows: GPURasterizer::Draw median 99.5 ms, p90 133 ms, max 467 ms, 8.1 s of raster in about 10 s of scrub. The bridge cost little: Java DartMessenger send 11.2 ms in total, Dart DispatchPlatformMessage max 5.2 ms.

boo-duaq changed four things. The WebView uses texture-layer composition (useHybridComposition: false), so raster runs on the raster thread. The page image travels as raw JPEG bytes through a WebMessageListener (canvas.toBlob, an ArrayBuffer of a 4-byte request number and the JPEG), not as base64 in the JSON result. The hidden rendition opens with the book, beside the shown page, and resizes before each preview. A preview yields between steps and stops when the deck abandons its place.

After: no Choreographer warnings in a full scrub. UI frame BUILD max 4.0 ms, Animator::BeginFrame p50 0.0 ms, p90 2.1 ms. Image message: Java max 2.4 ms, Dart max 2.2 ms.

Time per page, from request to image arrival in Dart, before the decode: median 382 ms (306 to 483 ms) over one scrub, against 0.6 to 1.7 s in boo-foo7 (with decode). The decode runs off the UI thread. The 0.3 s goal is not met yet on the emulator. The rest is epub.js layout of the hidden rendition and the canvas draw; measure on a phone (t6-6gej) before more work.
