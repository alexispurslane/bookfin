# Write page maps while Downloads owns the download

Found in t5-4l4d. The page source writes a book's page map once the whole book is laid out, which can be long after the open's readLocalFile call ended. If the person removes the download at that moment, the write can create .bookfin-layout again after DerivedBookFiles.remove ran and before the download's directory is removed. Then the directory keeps a page map (at most 70 KB) and is not removed. Route page map writes and forgets through Downloads' read ownership, as the OCR text supply does (session.dart binds it with downloads.readLocalFile), or make the store refuse to create the layout directory when the download's complete file is gone.

## Acceptance Criteria

A test removes a download while the page source writes its page map, and the download's directory is gone afterwards.
