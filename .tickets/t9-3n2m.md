# The PDF viewport gets page text from the document and reports recognition choices

Rules: UI rule 1 (only controllers cause side effects, no long-lived data in a leaf State). Engine rule 1 (no repeated heavy CPU work on the UI isolate).

Breaks:
- lib/reader/pdf_viewport.dart, _PdfViewportState._load and the recognition buttons: the viewport asks the document for page text, which can start OCR. It keeps the text and the page image in its State, and calls textSupply.cancel and textSupply.retry from its own "Cancel recognition" and "Retry recognition" buttons.
- lib/reader/pdf_viewport.dart, _reflow: the reflow choice lives in the leaf State and is lost when the reader closes.
- lib/reader/pdf.dart, PdfBook.addressFor: computes sha256 of the whole page text for each address. The viewport asks for an address on each scroll change, on the UI isolate.

Target design:
PdfBook stays the owner of page text and recognition. The viewport gets the current page's text and the recognition state through listenables from the document or the session. It reports onRetryRecognition(page), onCancelRecognition and onReflow(bool) to ReaderScreen, which calls the session. The digest of a page text is computed once for each page text, not once for each address. The viewport keeps only ephemeral state, such as the scroll offset and the layout.

Decided by the user on November 7, 2026: Option B. ReaderSession keeps the reflow choice for this run of the app. It resets to Original page after a restart.

Former open decision: whether the reflow choice outlives the reader.
- Option A: remember it for each edition in the reading records, so it syncs with the place. Cost: a new reading record field, a record format change and a sync change.
- Option B: keep it in ReaderSession for this run of the app. Cost: the choice resets to Original page after a restart.

Owned files: lib/reader/pdf_viewport.dart, lib/reader/pdf.dart, lib/reader/screen.dart (the PdfViewport call site), lib/reader/session.dart (if the reflow choice moves there), and their tests.

## Acceptance Criteria

- Cancel recognition reports up, and the screen cancels through the session (a recording fake).
- Scrolling inside one page computes the page digest once (a counting test).
- The reflow choice behaves as the open decision says (test).
- PdfViewport calls no textSupply method (a fake that throws proves it).
