# Keep personal records that this build cannot read yet


Design: docs/plans/reading-history.md, "Older builds". Order of work 1. No user decision needed.

Today `RecordJournal._validate` (lib/sync/journal.dart) rejects an address whose collection it does not know, and `_validateActionValue` (lib/playback/store.dart) rejects a value that does not decode. So an older build stops its discovery at the first record of a newer kind, and its sync fails until it updates. Make each build keep such a record instead.

Build:

- Take an action with a valid envelope at an address that this build does not know. The journal keeps it, applies it in causal order, and syncs it. No view shows it, and no writer changes it.
- The same rule applies to a value of an unknown kind at a known address. An example is a history event with an unknown `kind`.
- A value at a known address that fails to decode for another reason is still damage, and the existing damage path applies.
- Document the rule in the class comment of `LocalResumeStore`.

## Acceptance Criteria

- A store that receives an action at `["reading", "history", id]` before reading history exists keeps it, advances its discovery cursor, and shows no change in either view.
- A later build that knows the collection shows that record, without a new sync.
- A listening event with an unknown kind is kept and not shown. The rest of the listening history shows.
- A malformed listening event at a known address still counts as damage, as before.
- A kill during the save of such an action keeps all of the save or none of it.
