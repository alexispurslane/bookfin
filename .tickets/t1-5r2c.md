# Show the page number in the chapter for native EPUB pages

The reader dock's place label (screen.dart _pageLabel) shows 'Page 2 of 8' from ReadingLocation.page and pages. The WebView reader takes both from epub.js's displayed page of the section. pageLocation (tc-sqp7, lib/reader/epub/places.dart) writes no page and no pages, because its interface gets neither, so the native reader would show 'Page progress unavailable'. While the main run of a section has not reached an anchored page (design 'Pages', rule 3), the page index and the page count are not known.

Product fork: (a) show 'Page N of M' only after the main run of the section ends, and 'Page N' or nothing before; (b) show the text progress through the book (as the scrub bar does for EPUB) instead of a page number. The pager (tc-mxfp) or the session owns the choice. page and pages are not saved (toJson leaves them out), so either choice keeps saved places unchanged.

**2026-11-08T22:09:07Z**

As built: the page number is not in the reported address, because opening at a saved place must report the saved address object unchanged (tc-mxfp) and a settings change reports nothing. The design says nobody stores the page index; it follows from the shown page. So the pager publishes ValueListenable<PageNumber?> pageNumber, PageNumber = ({int number, int? count}): number is the count of true page starts at or before the shown page's start, null until the section's main run passes that start; count is the section's true page count, null until the main run ends. It updates while the page stays shown. PageSource gained numberOf(LaidPage) and mainRun(LaidPage, {end, abandon}), which waits at the shown section's main-run rank. The dock label itself is in screen.dart, which tc-1yif owns: show 'Page N' from number, then 'Page N of M' with count; while number is null the label keeps today's text for no page.
