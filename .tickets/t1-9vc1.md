# A page can hold only the border of an empty block after an overflowing page

Found in tc-4f3q (corpus run with its blank-page check). Two Gutenberg sections end with a page that shows only four rules, 2 pixels tall, at both corpus page settings:
- The Divine Comedy (pg-8800), section 2 (OEBPS/..._8800-h-1.htm.xhtml): page 0 holds one image paragraph and is 681.9 pixels tall on a 671-pixel page. Page 1 is PageStart(7, 0), the border of an empty block.
- Through the Looking-Glass (pg-12), section 3 (OEBPS/..._12-h-2.htm.xhtml): page 0 holds a table and is 704 pixels tall. Page 1 is PageStart(8, 0), the border of an empty block.
A reader sees a page with a thin line on it. Chromium's columns can push such a border to the next column as well, so compare with Chromium (or the committed fidelity data) before changing the cut.

## Acceptance Criteria

- The comparison with Chromium is recorded.
- If Chromium does not make such a page, no page of these two sections shows only rules, and the corpus run's blank-page check passes for both books.


## Notes

**2026-11-09T07:37:03Z**

Compared with Chromium (2026-11-09): epub.js in headless Chromium (the WebView reader's page, 412 x 671 at 20 pixels, via a copy of packages/flutter_epub_viewer/engine/trial/compare.cjs that only counts pages and takes screenshots) cuts two pages for The Divine Comedy section 2 and for Through the Looking-Glass section 3, and the second page of each shows only a thin rule at its top, as the native renderer does. So the cut stays. The corpus blank-page check now counts only pages that draw nothing (no line, image or rule), and both books pass it at both page settings.
