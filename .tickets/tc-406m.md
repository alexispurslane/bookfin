# Footnote links (product decision needed)

Goal: decide and build what a tap on a footnote reference does. This waits for the user's choice between the two options in the design section "Product fork for the user".

- Option A, follow the link as today: a tap on a note reference goes to the note like any internal link. The note's back link returns to the text. The saved place moves to the note. Cost: no code beyond tc-1iap's links. If the user picks A, record the decision and close.
- Option B, show the note over the page: a tap on a note reference (epub:type noteref, or a link whose target's epub:type has footnote, endnote, rearnote or note) shows the note's text in the reader's plain bottom sheet. The page and the saved place do not move. The sheet has 'Go to note'. Cost: note detection in places.dart, a layout run over the note element for the sheet in pager.dart, the sheet in screen.dart, and tests.

Files: decided with the option. Option B: lib/reader/epub/places.dart, lib/reader/epub/pager.dart, lib/reader/screen.dart and tests.

## Design

docs/plans/native-epub-reader.md (epic boo-b2ey). Read the sections named in the description. The design decides the owners, interfaces and order. Ask the orchestrator before changing them.

## Acceptance Criteria

Written after the user's decision. For option B at least:
- A tap on a note reference shows the note's text and moves no place.
- Go to note shows the note.
- A link that is not a note reference still jumps.
