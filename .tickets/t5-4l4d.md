# Open a book with its kept page map

Found in boo-ystu (docs/research/epub-layout-cache.md). Seed the page source with the kept page map at open, check it on use, and save each section whose main run ends. The map reads in parallel with the admitted book, and the page source never waits for it. A seeded section has its starts and mainDone, so pageAt gives the true page at once, numberOf gives the number and count at once, and the whole-book work of t7-bbv1 neither prepares nor lays out that section. A page from a kept start lays out only its strip, in the run from a known start (today's anchored run). Check on use: when a run lays out the page at kept start S and finds a following start that is not the next kept start, or the page's last flag disagrees with the map, the map for these settings is stale: drop it from memory, delete its file, and lay out main runs again. At open, the shown true page must hold the saved place; else show the anchored page at the line. Save after a section's main run ends, at most once every few seconds, and when the book closes or the app goes to the background. In the survey, every one of 124,643 corpus pages laid out from its kept start equals the main run's page, and three processes cut the same starts.

## Acceptance Criteria

After the first whole-book layout of a book, a second open of it on the emulator shows whole-book page numbers at once and does no prepare or layout for sections that the reader does not visit. A test with a page map edited to be wrong shows no skipped or repeated text, drops the map at the first page that contradicts it, and opens every saved place on a page that holds it. A test opens every saved place of a corpus book with and without a page map, and both show the same place.


## Decision (user, 2026-11-09)

Design A of docs/research/epub-layout-cache.md: trust the kept page map at open and spot-check each page that the reader views. A mismatch deletes the map and the book lays out again. Do not re-run the whole-book layout at every open (design B).

## Notes (2026-11-09)

The loaders (platform_io.dart, mobi.dart) give it to `EpubDocument.pageMaps`. A debug build's fingerprint is null, so its store reads nothing and writes nothing.
